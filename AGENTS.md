# AGENTS.md

> This is the single canonical guidance doc for this repo. `CLAUDE.md` is a symlink to it, so Claude Code and any AGENTS-aware tool read the same content. **Edit this file** — never `CLAUDE.md` directly (it has no independent content).

## What this repo is

A personal macOS dotfiles tree mounted at `~/.config`. The `README.md` lists the tools at a high level (tmux, ghostty, zsh+ohmyposh, nvim, aerospace, sketchybar, jankyborders, raycast). There is no build / test / lint pipeline — work happens by editing configs and reloading the live tool.

## Commits

**The user commits all changes manually. Never run `git commit`/`git add`/push in this repo — not even when work is finished or verified.** Make the edits, report what changed, and stop; the user stages and commits themselves.

## Source-of-truth files (not obvious from directory layout)

- **`COLORS.md`** — palette guide and the canonical source of truth for every color used across tools. Lists semantic roles (`canvas`, `surface-active`, `surface-chrome`, `surface-highlight`, `divider-subtle`, `text`, `text-muted`, accent-*) with hex values and per-tool usage. Also has a `Cross-tool consistency` section flagging known near-misses, a `Claude Code integration` section documenting the custom theme, and a `Git colors (cross-tool)` table. **When changing any color anywhere, consult this file first.** When introducing a new color, add or extend a role rather than scattering inline hex.
- **`claude/themes/vague-aligned.json`** — custom Claude Code theme (requires Claude ≥ 2.1.118). Bases on `dark-ansi` and overrides ~11 semantic tokens to lock Claude's UI to the palette. Activated via `"theme": "custom:vague-aligned"` in `claude/settings.json`. Tokens not listed here intentionally inherit from `dark-ansi` (Ghostty's ANSI palette) — **including code-block syntax highlighting**, which is not themeable via the JSON (see the Claude Code integration section).
- **`claude/statusline-command.sh`** — custom two-line Claude Code statusline. Emits 24-bit ANSI escape codes; reuses palette colors keyed off the same roles `COLORS.md` defines (muted, branch, dirty, delete).
- **`claude/plans/`** — Claude Code plan-mode session artifacts (gitignored). Safe to read for context on prior planning; do not treat as authoritative documentation.
- **`ghostty/themes/vague`** — the base color palette file. **Do not edit this when adjusting the user's effective palette** — instead override the specific keys (`background`, `foreground`, etc.) in `ghostty/config`. Keeps the theme file reusable.
- **`tmux_scripts/`** — referenced from `tmux.conf` for popup / session / pane management. Not a tool directory; it's a script bundle.
- **`tmux_scripts/tsave` + `tmux_scripts/tload`** — session snapshot/restore. `tsave [name]` walks every session → window → pane to `~/.config/tmux_sessions/<name>.{json,md}` (the `.md` is the human-readable `SESSIONS:` tree; Claude Code panes are recorded with their `sessionId`, recovered via the pane's process tree → `claude/sessions/<pid>.json`). `tload <name|path>` recreates them — skipping sessions that already exist, restoring pane geometry from the saved `window_layout` string, and relaunching only `claude` panes via `claude --resume <id>` (every other pane returns as a plain shell in its saved cwd, no command replay). Snapshots live in `~/.config/tmux_sessions/`, gitignored via `.git/info/exclude` (not the tracked `.gitignore`).
- **`aerospace/aerospace.toml`** — tiling WM config; also the launcher of `sketchybar` + `borders` (via `after-startup-command`). Keybinds route through shell scripts in `aerospace/` (`keyswap.sh`, `cycle_workspace_window.sh`, `move_workspace_cycle.sh`, `toggle_gaps.sh`, `toggle_keyswap.sh`) and Hammerspoon (`hs -c "..."`). Workspaces `1*`–`5*` are force-assigned to `main`; `1^`/`2^` to secondary (`dell`/`built-in`).
- **`sketchybar/sketchybarrc`** — the bar config; items + event subscriptions are defined inline. Plugins in `sketchybar/plugins/` are executed by sketchybar via `script=`. The bar is launched by AeroSpace's `after-startup-command`, not by a launchd/brew service.
- **`hammerspoon/window.lua`** — all window sizing/float logic; frames computed directly (no Rectangle). `init.lua` exports the functions as `_G` globals so AeroSpace callbacks and `hs -c "..."` can call them by name.
- **`hammerspoon/bar.lua`** — SketchyBar profile toggle (`toggleMode`), reload (`reload`), and AeroSpace server toggle (`toggleAerospace`); also shrinks `hs.alert.defaultStyle` globally. Exported as `_G.toggleBarMode` / `_G.toggleAerospace`.
- **`sketchybar/sketchybarrc.full` + `sketchybar/sketchybarrc.performance`** — the two bar profile sources of truth (full vs. performance). The bare `sketchybarrc` is a copy that gets overwritten on each `cmd-ctrl-alt-p` toggle — always edit the `.full`/`.performance` files directly. `toggle_mode.sh` does the copy + flag flip.
- **`KEYBINDS.md`** — full reference of every active keybind across AeroSpace, Hammerspoon, and tmux (core binds + plugin/integration sub-keys). **When you add/remove/rebind a key, update this file to match.** Organized by tool → function group, with root vs. prefix scope noted for tmux binds.

## Cross-tool palette discipline (the main "architecture")

The palette is enforced *by convention*, not tooling. Nine surfaces share colors:

- Ghostty (`ghostty/config` overrides + `themes/vague` ANSI palette)
- tmux (`tmux.conf` — `@color-*` user options + inline hex)
- zsh prompt (`ohmyposh/base.json` — segment-by-segment hex)
- nvim theme (`nvim/lua/plugins/vague.lua` — `colors` override + `on_highlights`)
- nvim chrome (`nvim/lua/plugins/lualine.lua`, `nvim/lua/plugins/dropbar.lua`, `nvim/lua/plugins/devicons.lua`)
- nvim diagnostics / gitsigns (via `vague.lua` `on_highlights`)
- nvim FoldColumn / NonText / FloatBorder / render-md heading backgrounds (also via `vague.lua` `on_highlights`, see the `surface-fold`, `surface-extend`, `surface-heading-h1/h2/h3`, `text-ui` roles in `COLORS.md`)
- Claude Code UI (`claude/themes/vague-aligned.json`)
- Claude Code statusline (`claude/statusline-command.sh`)

When a user asks to change a color, the change usually touches **2–4 of these surfaces**. Default workflow:

1. Identify the affected role(s) in `COLORS.md`.
2. Find every usage via `grep -rn '<hex>' ~/.config` (excluding `.git`, `claude/plans`, `claude/projects`, `nvim/lazy-lock.json`).
3. Edit all sites in one pass and update `COLORS.md` to reflect the new value or new role.
4. Hex case is *not* normalized — files have a mix of `#1c1c24` and `#1C1C24`. Don't normalize unprompted; both are functionally identical.

## Bar + window-management stack (AeroSpace / SketchyBar / Hammerspoon)

Three tools are wired together: AeroSpace emits callbacks on workspace/focus change → SketchyBar renders the bar → Hammerspoon does all window sizing/float (AeroSpace only tiles; Hammerspoon owns floating-window geometry).

**When changing aerospace/sketchybar/borders, cross-check dependents before considering the change complete.** These three are consumed by other programs, not just each other: Hammerspoon (`bar.lua`, `gaming.lua`) sources `bordersrc` and reloads `sketchybarrc`, `aerospace.toml`'s `after-startup-command` launches both, and `tmux_scripts/` shells out to `aerospace`. A change that looks self-contained in one file (e.g. `bordersrc`'s bare `borders` call, or `sketchybarrc`'s bar-level `drawing` state) can silently break a caller that invokes it under a different environment or process lifecycle. Grep `hammerspoon/`, `aerospace.toml`, and `tmux_scripts/` for the thing you changed before moving on.

**AeroSpace callback syntax differs per key (`aerospace/aerospace.toml`).** This is a recurring footgun:
- `exec-on-workspace-change` (and other `exec-on-*-change` callbacks) take an **external process argv** array: `['/bin/bash', '-c', '…']`. Do **not** prefix with the `exec-and-forget` AeroSpace command token — that is not a binary, and adding it silently breaks the callback. The callback runs sync; keep it cheap.
- `on-focus-changed` and keybinding entries take the **AeroSpace command string** form: `'exec-and-forget sketchybar --trigger …'` (single TOML string, `exec-and-forget` is a real command here). Binding entries can also be arrays mixing AeroSpace commands and `exec-and-forget` strings.
When in doubt, check the AeroSpace guide: callbacks spawn a process from argv; bindings run AeroSpace commands.

**SketchyBar events drive the bar (`sketchybar/sketchybarrc` defines 3 custom events):**
- `aerospace_workspace_change` — fired by AeroSpace's `exec-on-workspace-change` with `FOCUSED_WORKSPACE`; subscribers: `ws_1` (→ `frontapps.sh`) and `space.1^` (→ `space_colors.sh`).
- `aerospace_focus_change` — fired by `on-focus-changed`; subscriber: `ws_1` (→ `frontapps.sh`).
- `aerospace_keyswap_change` — fired by `toggle_keyswap.sh`; subscriber: `keyswap` item.
- **Never use `sketchybar --update`.** It forces *every* script to run at once; on monitor-attach (SketchyBar destroys/recreates all bars) this multiplies into heavy fanout and visible lag. Initial render uses targeted `--trigger` calls instead (end of `sketchybarrc`). If you add an item whose script must run at startup, add a corresponding `--trigger`, not `--update`.
- **`frontapps.sh` is the heavy plugin** (~2 aerospace IPC queries + awk/sort + a borders-color diff per run). It has a leading-edge coalescing lock (`mkdir` atomic lock + pid guard + dirty flag) because a workspace switch fires both `aerospace_workspace_change` and `aerospace_focus_change` concurrently — don't bypass the lock or you'll re-introduce the double-run race. It rebuilds up to 7 workspace slots × 6 app slots + separators in one batched `sketchybar` call.
- **`space_colors.sh` is the single driver for all `space.*` indicator colors** — only `space.1^` subscribes to the event; the script batch-colors every `space.*` item in one call. When you add/remove a center `space.*` item, update the sid list in `space_colors.sh` to match or that item's color goes stale.
- **`sketchybar/plugins/aerospace.sh` is legacy/dead** — it was the old per-item color script replaced by the batched `space_colors.sh`. It is not wired to any active item; don't wire it back.
- **Center block layout is `* *-*-* *`**: workspace indicators are still `1^ 1* 2* 3* 2^`, but the middle three are visually connected (`*-*-*`) and there is **no overline**. The connectors are labels (`-`) on `space.1*`/`space.2*` with a fixed inactive color; active state is icon-only (`space_colors.sh` recolors `icon.color` only), so only the star highlights. `4*`/`5*` are intentionally NOT rendered as center indicators but remain reachable via keyboard (`cmd-4`/`cmd-5`) and shown in the left block when occupied. Don't re-add `4*`/`5*` to the center loop or to `space_colors.sh` without being asked. `space.1^` still subscribes to `aerospace_workspace_change` and drives `space_colors.sh` for all five.
- **Don't batch the right-block items into one `sketchybar` call.** The left block (one big `CMD` array of ~84 items) batches fine, but batching the right block (`battery` / `sep_right` / `date`) into a single `--add ... --set ... --add ... --set ...` call causes the right-block items to stack on top of the center block. Keep the right block as 3 separate `sketchybar --add item ... --set ...` calls (the form that works). The center→right gap is set by `icon.padding_right=16` on `space.2^` (the rightmost center star); adjust that single value to tune the gap.
- **Performance mode — two decoupled keybinds, driven by `hammerspoon/bar.lua`:**
  - `cmd-ctrl-alt-p` (`bar.toggleMode`) — swaps the active profile by *copying* the chosen profile over `sketchybarrc` + flips `/tmp/sketchybar_perf_mode`. **Does NOT reload** — intentionally decoupled so you can stage a swap and apply it on your own timing.
  - `cmd-ctrl-alt-o` (`bar.reload`) — restarts the bar: `pkill -x sketchybar` → `sleep 1` (lets the killed daemon release its mach service port) → `nohup sketchybar -c sketchybarrc`, all in a backgrounded subshell with `PATH=/opt/homebrew/bin` exported so the config's internal bare `sketchybar` calls resolve. Deliberately NOT `--reload` (see the `--reload` bullet below).
  - Profiles: `sketchybarrc.full` (full setup — source of truth, edit this) and `sketchybarrc.performance` (right-block-only: date + battery, `blur_radius=0`, no AeroSpace events, renders on ALL displays — no `display=` key so it uses sketchybar's `all` default). Copy, not symlink — sketchybar reloads a plain file unambiguously. `toggle_mode.sh` does the copy + flag flip and echoes the new mode; Hammerspoon shows a lowercase `hs.alert` (`bar: full` / `bar: performance`).
  - The `/tmp/sketchybar_perf_mode` flag also gates the AeroSpace callbacks in `aerospace.toml` (`exec-on-workspace-change` / `on-focus-changed` no-op while the flag exists) so workspace/focus switches incur zero bar IPC in perf mode.
  - On the first toggle, if `sketchybarrc.full` is missing the script migrates it from the current `sketchybarrc`. **Always edit `sketchybarrc.full` / `sketchybarrc.performance` directly** — the bare `sketchybarrc` is just a copy that gets overwritten on each toggle.
  - `hs.alert.defaultStyle` is shrunk globally in `bar.lua` (textSize=14, radius=8) so alerts render as small pills, not the default huge centered overlays.

**Hammerspoon window sizing (`hammerspoon/window.lua`):**
- `init.lua` exports `_G` globals so `hs -c "<fn>()"` works from AeroSpace: `almostMaximize`, `almostMaximizeAfterMove`, `center`, `center43`, `almostMaximizeAll`, `almostMaximizeFocusedWorkspace`, `fullMaximize`, `toggleFloatKeepPos`, plus `toggleBarMode` and `toggleAerospace` from `bar.lua`. When you add a window function that AeroSpace calls, export it here.
- **`cmd-ctrl-alt-*` keybinds** (all bound in `init.lua`): `c` = `almostMaximizeFocusedWorkspace` (workspace-wide, display-wide fallback), `x` = `almostMaximize` (big-gap inset), `b` = `center43` (4:3 centered, smaller than `x`; `scale=0.8` knob in `window.lua`), `v` = `maximize` (small-gap inset), `shift-v` (= `cmd-ctrl-alt-shift-v`) = `fullMaximize` (same left/right as `v`, top inset = bottom inset so the window covers the SketchyBar strip — distinct from `v` which uses a larger bar-clearing top), `space` = `center` (no resize), `p` = bar profile swap (no reload), `o` = bar reload, `shift-o` (= `cmd-ctrl-alt-shift-o`) = `toggleAerospace` (enables/disables the AeroSpace server). Don't rebind these without checking AeroSpace `hs -c "..."` callers don't depend on the same combo.
- **PATH gotcha:** Hammerspoon is a GUI app; `os.execute`/`hs.execute` run with an env that typically lacks `/opt/homebrew/bin` in `PATH`. A bare `sketchybar` or `aerospace` in those calls is silently "command not found" (often hidden behind `2>/dev/null`). Always use absolute paths (`/opt/homebrew/bin/sketchybar`, `/opt/homebrew/bin/aerospace`) — this is the convention in `window.lua` and `bar.lua`. Same applies to shell scripts Hammerspoon spawns via `/bin/bash <script>`. **This bit `borders/bordersrc` too** — it called bare `borders "${options[@]}"` internally, which resolved fine from AeroSpace's `after-startup-command` (has a normal PATH) but silently failed when `hammerspoon/gaming.lua` sourced the same script via `/bin/bash` on toggle-out of gaming mode. Fixed by hardcoding the absolute path inside `bordersrc` itself, so every caller is safe regardless of environment — don't revert that to a bare `borders` call. **Same bug bit `gaming.lua`'s sketchybar restore** — `hs.task.new(SKETCHYBAR, {"-c", RC})` inherited Hammerspoon's PATH-less env, so `sketchybarrc`'s internal bare `sketchybar` calls silently failed and the bar came up at raw defaults after exiting gaming mode. Fixed by wrapping the launch in `/bin/bash -c "export PATH=/opt/homebrew/bin:$PATH; exec ... sketchybar -c ..."` — keep that wrapper. (`bar.lua`'s reload has the same PATH export for the same reason.)
- **`gaming.lua`'s exit-gaming-mode branch sources `borders/bordersrc` directly** (`hs.task.new("/bin/bash", nil, {HOME .. "/.config/borders/bordersrc"})`) rather than keeping its own hardcoded copy of the `borders` launch args. It used to duplicate them inline and drifted out of sync with `bordersrc` (different `style`/`hidpi` values) — sourcing the same file is the single source of truth; don't reintroduce a duplicated args list here.
- **SketchyBar's `--reload` doesn't always reach a genuinely stale/hung process.** `sketchybarrc.full`/`sketchybar.performance` didn't explicitly set `drawing=on` on the `bar` array, and since `--reload` replays config on the *same* running process rather than restarting it, a stray `--bar drawing=off` from any earlier debugging session persists across every subsequent reload until the process is actually killed and relaunched (or the value is explicitly set again). Both profile files now set `drawing=on` explicitly in the `bar=(...)` block as a self-heal, matching the existing exec-bit self-heal convention at the top of each file. If the bar ever renders with 0 items / default styling (`height=25`, `color=0x44000000`, etc.) after a reload, that's this class of bug — `pkill -x sketchybar` and relaunch (`sketchybar -c ~/.config/sketchybar/sketchybarrc`) rather than trying another `--reload`. `cmd-ctrl-alt-o` (`bar.reload`) automates exactly this kill+relaunch. Also: **never chase a fresh `-c` launch with a `--reload`** — reload replays the config on the running process, re-adds the right-block items (`battery`/`sep_right`/`date`), and stacks them overlapping each other. A cold `-c` launch renders the right block correctly on the first pass; the overlap only appears after a reload.
- **`cmd-shift-s` (aerospace.toml) does two things via `toggleFloatKeepPos`.** It always toggles the focused window's float/tiling state, keeping its on-screen frame when it becomes floating. Additionally, if the window that just became floating is Ghostty or Firefox, it checks for that app's counterpart (Ghostty↔Firefox) on the same workspace via `aerospace list-windows --workspace focused --format '%{window-id}||%{app-name}||%{window-layout}'`; if the counterpart is also floating, both get snapped side-by-side (half-screen each, `ALMOST` gap insets, 16px gap between) via `snapSideBySide`. Ordering (which window lands left vs right) follows whichever window's current center-x is further left. This is layered onto the existing toggle, not a separate keybind — no `aerospace.toml` change was needed.
- **`toggleFloatKeepPos` force-syncs AeroSpace's focus before toggling.** It captures/restores the frame of Hammerspoon's `hs.window.focusedWindow()`, but the actual float/tiling toggle is issued via AeroSpace's own `layout floating tiling` command, which acts on AeroSpace's separately-tracked focused window. AeroSpace updates focus via async accessibility notifications and can lag briefly behind the true OS focus (reproducible by scripting a fast app switch), so the two can desync — symptoms were cmd-shift-s silently doing nothing on a genuinely-focused window, or toggling one app flipping a *different* app's float state instead. Fixed by running `aerospace focus --window-id <id>` (for Hammerspoon's focused window) immediately before `layout floating tiling`, so both always act on the same window. Don't remove that `focus --window-id` call thinking it's redundant.
- **`almostMaximizeFocusedWorkspace` (cmd-ctrl-alt-c) has a display-wide fallback.** When AeroSpace is active it floats + snaps every window on the focused workspace (the original behavior). When AeroSpace is disabled/paused/uninstalled it instead snaps every standard visible window on the focused window's display (no AeroSpace IPC, no float step — windows are already free-floating without the WM); if there's no focused window it snaps all visible standard windows. Detection is via an `aerospace list-windows --all` probe (`aerospaceAvailable`), not by empty output (an empty workspace vs. a disabled server are indistinguishable by output alone).
- Two inset presets mirror AeroSpace gaps: `ALMOST` (big gaps) and `MAXIM` (small gaps). **These must stay in sync with `toggle_gaps.sh`'s `BIG_*`/`SMALL_*` constants** — both encode the same two gap states for floating vs tiled windows. `toggle_gaps.sh` rewrites the `[gaps]` table in `aerospace.toml` via `sed` then `aerospace reload-config`; the Hammerspoon presets are hardcoded px values matching the same geometry.
- **`almostMaximizeAfterMove()` is a debounced snap**, used only for cross-monitor moves (`cmd-shift-w`). The Accessibility API can report the *old* screen for a few ms after `move-node-to-monitor --focus-follows-window`, so an immediate `snapInsets()` computes the frame against the wrong monitor and the window lands off-center/on the wrong display. It polls the focused window's `screen():id()` until stable (or ~250ms timeout). Don't replace it with the immediate `almostMaximize()` for cross-monitor binds. Within-monitor binds (`cmd-ctrl-1..5`, `move_workspace_cycle.sh`) don't need it — `1*..5*` and `1^..2^` are each force-assigned to a single monitor, so screen identity can't change.
- **`rectangle-keybinds.lua` is disabled** (the `require` is commented in `init.lua`); window sizing is pure Hammerspoon via `window.lua`. Don't re-enable it.
- **`hammerspoon/drag.lua`** is a global mouse eventtap (`cmd-ctrl` + left-click-drag moves the window under the cursor, any app), added because Ghostty runs with no visible native frame (`macos-titlebar-style = hidden`; previously `window-decoration = false`), leaving no titlebar/frame drag handles. Requires the **Input Monitoring** TCC permission (separate from Accessibility) for Hammerspoon — a fresh grant only takes effect after a full Hammerspoon relaunch, not just Reload Config. **Gotcha:** don't call `hs.window.frontmostWindow()` (or any other Accessibility-API round-trip like `:title()`) synchronously inside the eventtap callback's hot path — it pumps the CFRunLoop while waiting on the target app's AX reply, which can let the *next* queued mouse event reach the same callback reentrantly before the first call finishes, corrupting shared state (`dragging`/`dragWindow` got read before being set). `drag.lua` works around this by caching the focused window via an `hs.window.filter` focus-changed subscription (updated only on real focus changes) instead of querying fresh on every click.

## nvim plugin internals (non-obvious)

- **Trouble keymaps route through `nvim/lua/utils/trouble.lua`, not `require("trouble").toggle` directly.** All the `<leader>x*` mappings in `whichkey.lua` call `trouble_helpers.toggle(mode)`, which calls `M.open(mode)` → `view:wait()` + `view:fold_level({ level = N })` for mode-specific initial fold depth (symbols/lsp = 3, diagnostics/qflist = 2). If you add a new trouble keymap and bypass the helper, you lose the auto-fold behavior. If you add a new mode, add its fold level to the `fold_levels` table in the helper.
  - `M.open` defaults `focus = true` (keybind opens focus the window). `<leader>xt` position toggle in `trouble.lua` explicitly passes `{ focus = false }` to keep cursor in the editor. Don't change the helper default without checking `<leader>xt` still passes `focus = false`.
  - `position_pairs` in `trouble.lua` is an **ordered array** iterated with `ipairs`, not `pairs()` over a table — Lua table iteration order is non-deterministic and was causing inconsistent `<leader>xt` behavior when multiple Trouble modes were open. Keep it as an ordered array.
  - trouble v3 does **NOT** emit a `User TroubleOpen` event. An earlier config used a `User TroubleOpen` autocmd to fold-on-open; it was dead code and has been removed. Don't reintroduce it.
- **Noice cmdline UI hides the native `:` cursor.** `noice.lua` currently has `cmdline.enabled = true, view = "cmdline"`. Noice renders the cmdline itself (`noice/ui/cmdline.lua`), which sometimes leaves no visible cursor when pressing `:`. If the user reports the cursor is gone, set `cmdline.enabled = false` in `noice.lua` to restore the native cmdline (messages and popupmenu still use Noice). Don't disable `messages.enabled` — that's a separate concern.
- **`vague.lua` `NonText` override has cascading side effects.** `listchars.extends`/`precedes` use the `NonText` highlight group, which is also inherited by path-like UI surfaces, end-of-buffer tildes, and other nontext elements. Setting `hl["NonText"] = { fg = ..., bold = true }` to make `»/«` more visible will recolor all of those. The decision was to **not** override `NonText` and instead rely on the glyph choice in `listchars` alone. The override line is left commented in `vague.lua` (line ~101) with a one-line note; the dim reset groups (`BlinkCmpGhostText`, `LspInlayHint`, `GitSignsCurrentLineBlame`, `ComplHint`) below it are intentional restoration styling and should stay even if the override stays commented.
- **render-markdown keeps fence/dash lines visible by config, not by default.** `render-md.lua` sets `code.conceal_delimiters = false`, `code.border = "none"`, `code.background_inset = 0`, and `dash.enabled = false`. The plugin defaults conceal ` ``` ` fence lines, replace `---` with a virtual text line, and skip the fence lines from the background highlight — all of which the user has explicitly overridden. If you're asked to "make code blocks look nicer" or "tweak rendering," don't reset these to defaults; the user has already decided raw ` ``` ` and `---` lines should stay visible. `background_inset = 0` extends the `RenderMarkdownCode` background to cover the fence lines so they match the code body.
- **`<leader>pl` preview float is a non-focusable, close-on-action float.** Defined in `vim-keymaps.lua`, tracked via a module-local `preview_float_win` variable. It is opened with `enter = false`, `focusable = false`, anchored to the cursor (`relative = "cursor"`), and closes on any next action (`CursorMoved` / `InsertEnter` / `BufLeave` autocmd, `once = true`). Buffer-local `q`/`<Esc>` maps don't work because the float never takes focus — the close-on-action autocmds are the only dismissal path. The line content is trimmed of leading indentation via `:gsub("^%s+", "")` before display width calculation and buffer write. Re-pressing `<leader>pl` closes any existing preview first.
- **snacks.nvim `image` module must stay explicitly disabled.** `nvim/lua/plugins/snacks.lua` sets `image = { enabled = false }`. Do not remove or change to `nil` — snacks' attach guards check `== false` strictly, so `nil` passes them and `Terminal.detect()` emits an XTVERSION probe (`\e[>q`) whenever the picker previews a markdown file. tmux mangles the DCS reply (tmux#4386), leaking `>|ghostty 1.3.1` as literal text into the picker input. Inline images are not used; this must stay off.

## Notable conventions you'll meet

- **tmux dynamic styling via `command-alias` + hooks.** `tmux.conf` defines `refresh-active-bg` (a `set -g command-alias[200] '…'`) and wires it to 5 hooks (`after-resize-pane`, `window-layout-changed`, `after-new-window`, `after-select-window`, `pane-exited`). This is the workaround for tmux *style options* not supporting `#{?…}` format expansion. If you need similar dynamic behavior on another style option, follow the same pattern: alias + hooks, not inline format expressions.
- **tmux style vs format options.** `pane-border-format` accepts `#{}` and inline `#[fg=…]`; `window-active-style`, `pane-active-border-style`, and similar style options do not re-evaluate `#{?…}` per draw. Don't try to embed conditionals in style options.
- **tmux reload only SETS, never UNSETS.** `prefix r` (`source-file`) re-runs `tmux.conf` but does **not** remove hooks/options you've since deleted from the file, and per-pane `set -p` overrides persist regardless. After removing a `set-hook`/option, clear it on the live server (`set-hook -gu <hook>`, `set -pu -t <pane> <opt>`) or restart — otherwise the old behavior keeps firing. This repeatedly confused debugging of dynamic-styling work (each `set -p <style>` also triggers `recalculate_sizes` + a full redraw, so stale hooks cause flicker too).
- **nnn file-explorer popup (`M-d`) spans three layers.** `tmux.conf` `M-d` → `tmux_scripts/tmux-nnn-explorer` (a `display-popup` running `nnn`) which threads `NNN_ORIGIN_PANE='#{pane_id}'` + `NNN_PLUG` into nnn's env; the `nnn/plugins/` scripts (`tmux-split-h`/`-v`, `cd-origin`, shared `.nnn-tmux-split`) read `$NNN_ORIGIN_PANE` to `split-window`/`send-keys` back into the *originating* window — a popup isn't in the window tree, so the pane id must be passed in. Changing the explorer means reading all three layers.
  - **`nnn/plugins/preview-tui`** is the vendored upstream plugin with **7 local patches** (re-fetching it clobbers all of them): (1) `shopt -s extglob 2>/dev/null` after shebang (bash 3.2 fix); (2) debounce `while read -r -t 0.15 newer`; (3) CURSEL dedup; (4) large-file guard (`--line-range=:500` for >500 KB); (5) **`fifo_pager()` tempfile rewrite** — renders preview content to `$PREVIEWFILE` first, then branches by pager: **moor** is fed the seekable regular file (`moor < $PREVIEWFILE`) so mouse-scroll reaches EOF without stalling; **less** (and any non-moor pager) is fed via a FIFO (`less < $FIFOPATH`), because a backgrounded `less` renders **blank** from a seekable file in the preview loop (navigation previews launch from the backgrounded `preview_fifo` subshell, where `less` grabs the tty during line-map init) — it only paints over a pipe/FIFO; moor buffers its input and paints fine either way; (6) **`bat --wrap=never`** on the render call — bat was baking real newlines into the rendered file at the pane's terminal-width, which the pager can't undo downstream regardless of its own wrap setting. Preview defaults to no word-wrap because of this; `;w` (new `nnn/plugins/toggle-wrap`) sends the sibling preview pane's pager its own live wrap-toggle key (moor: `w`; less fallback: `-S`) to turn it back on for the current file; (7) **recolor the bat line-number gutter** — `--theme=ansi` emits zero color/style around the number column (verified: no escape codes even with `--color=always`), so bat's output is piped through `sed -E` to wrap the leading `<spaces><digits><space>` gutter in an explicit 24-bit `#606079` (`copy-mode-indicator` — the same muted/dim color nvim uses) instead of a new hardcoded color — only when `NNN_BATSTYLE` includes `numbers` (the default), the gutter format the regex assumes.
  - **`tmux-nnn-explorer`'s `NNN_SPLITSIZE` is `70`** (preview pane gets 70%, nnn listing gets 30%) and the popup itself is `-w65% -h75%` — narrower than the previous `60`/`80%`, to give the preview pane more room and the whole floating pane a smaller footprint (width only, height unchanged).
  - **`nnn/plugins/fzcd`** is the vendored upstream plugin with **local patches** (re-fetching clobbers them): (1) `--preview` + `--preview-window 'right,60%,border-left'` added to both fzf calls (bat for files, eza tree for dirs); (2) zooms the nnn pane (`tmux resize-pane -Z`) while fzf runs so it fills the whole popup, restoring the split on exit via a trap (guarded by `#{window_zoomed_flag}`); (3) global Meta keys (`M-q` abort, `M-j/M-k` move, `M-u/M-n` preview scroll, `M-g` jump to `fzrg`); (4) `bat --theme=ansi` + large-file guard (>500KB → `--style=plain --line-range=:300`).
  - **`nnn/plugins/fzrg`** has **local patches**: global Meta keys (same set as fzcd, `M-g` reloads search), `bat --theme=ansi`, `RG_COLORS` match underline style. Re-fetching clobbers these.
  - **`tmux_scripts/tmux-nnn-explorer`** forwards `FZF_DEFAULT_OPTS` and `RG_COLORS` into the nested `nnn` tmux session via `-e` env vars. Without this, `;f`/`;g` fzf colors differ from other fzf surfaces. Also selects the pager at launch: uses `moor --no-linenumbers --mousemode=scroll --statusbar=plain` if `moor` is installed (`brew install moor`), falls back to `less -R --mouse --wheel-lines=3 -+F`. `--statusbar=plain` makes moor's statusbar **and** its `---` EOF marker use the terminal default background (transparent) instead of the default `inverse` reverse-video (light gray). Also passes `nnn -l 1` for 1-line-per-notch wheel scroll in the listing (`-l` = lines per mouse-wheel notch; lower = finer/smoother, default 1).
- **extrakto (`M-K`) launch path + vendored patch.** `M-K` → `tmux_scripts/tmux-extrakto-launch` (sets `TMUX_OPEN_PANE` so the shared opener `tmux-open-target` can resolve/split off the origin pane, mirroring `NNN_ORIGIN_PANE`) → vendored `tmux_plugins/extrakto/scripts/open.sh` → `extrakto_plugin.py` in a popup. `tmux.conf` sets `@extrakto_fzf_unset_default_opts "false"` (keep the fzf palette) and `@extrakto_open_tool` (= `tmux-open-target`). **`extrakto_plugin.py` has 2 local patches (re-fetching clobbers them):** (1) `get_option_only` was rewritten to batch **all** global options via one `tmux show-options -g` into a process-lifetime cache (`_OPTION_CACHE` / `_load_options`), instead of forking `tmux show-option -gqv <name>` once per option (~28 reads). The per-fork form cost ~330ms of pure startup latency before fzf appeared; batched is ~40ms. The cache unquotes/​unescapes values to match `-gqv` exactly, and returns `""` for unset options (unset options aren't listed by `show-options -g`) — identical contract, verified zero mismatches. (2) Global meta keybinds (`alt-q:abort,alt-j:down,alt-k:up`) injected via `FZF_DEFAULT_OPTS` env var around the `fzf_sel` call, not via `--bind` in `fzf_cmd` — adding `--bind=alt-q:abort` to `fzf_cmd` causes fzf to exit with zero output (abort doesn't emit an `--expect` key), which triggers `ValueError` in the unpack. `FZF_DEFAULT_OPTS` merges cleanly with `--expect`. `alt-K` (toggle-close) is included — abort produces zero output (no `--expect` key), which is handled as a clean exit (`return 0` on empty result). No buffered-key issue because `FZF_DEFAULT_OPTS` is merged by fzf at startup, not passed as terminal input. The remaining variable cost is `@extrakto_grab_area "window full"` (default): captures up to `@extrakto_history_limit` (2000) lines from **every** pane in the window and tokenizes it all. If launch is still slow in a many-pane window with deep scrollback, narrow it (`recent` = visible viewport only / `full` = trigger pane full history) — that's a behavior change (which tokens are extractable), so it's a config choice, not applied by default.
- **tmux-fzf-url (`M-o`) vendored patch.** `tmux_plugins/tmux-fzf-url/fzf-url.sh` has **1 local patch** (re-fetching clobbers it): global meta keybinds (`alt-q:abort,alt-j:down,alt-k:up,alt-o:abort`) added to all three fzf invocation paths in `fzf_filter()`. The launcher (`tmux_scripts/tmux-fzf-url-open`) also adds a custom path regex (`PATH_PAT`) that surfaces file paths and bare filenames alongside URLs, routing files to nvim splits via `tmux-open-target`.
- **Ghostty config overrides theme.** Keys in `ghostty/config` win over values in `themes/<name>`. Set palette overrides (`background`, `foreground`) in `config`, not in the theme file.
- **`macos-titlebar-style = hidden` is back in use on Ghostty 1.3.2 / macOS 27.0 release** (`window-decoration = true` + `macos-window-buttons = hidden`), reintroduced to get rounded corners. History: a tip-build rendering regression on macOS 26/27 betas + AeroSpace (github.com/ghostty-org/ghostty/discussions/13320 — new windows painting opaque/blank until a config reload or split forced a redraw) pushed the config to `window-decoration = false` (fully undecorated, square corners). On 1.3.2 that desync did not reproduce, but `hidden` still leaves a **gray reserved titlebar strip at the top of the window** (same artifact class `transparent` had — the titlebar row stays reserved empty space). The user accepts the strip while waiting for an upstream fix. `window-decoration = false` is the documented square, artifact-free fallback if the strip or a desync regression becomes intolerable; if the desync reappears on a new build, revert to it.
- **`borders/bordersrc` is `style=round`, `width=5.0`, `active_color=0xffAEAED1`** (inactive `0xff1c1c24` unchanged) — matching the all-rounded window world now that Ghostty is rounded again via the hidden titlebar. The earlier `style=square` era existed to hug Ghostty's square `window-decoration = false` shape; if Ghostty falls back to that again, revisit whether square borders are wanted. **jankyborders has no per-app style** — `style` is global (`round`/`square`/`uniform`); the only per-app controls are `blacklist`/`whitelist` (which apps get bordered at all). **Operational gotcha:** running `borders <args>` with no daemon alive makes that invocation BECOME the daemon in the foreground and hangs — always launch backgrounded (`nohup borders ... &`). **Border color/width are locked project-wide** (see `COLORS.md`'s "Window borders" section): inactive `#1c1c24`, active-floating `#8B8692`, active-tiled `#AEAED1` (`accent-secondary` lavender, deliberately reused), width `5.0` — `bordersrc` (daemon defaults/fallback) and `sketchybar/plugins/frontapps.sh` (per-window layout override) must stay in lockstep on these values; don't reintroduce the old `#808080`/`#75758D`/`#bb9dbd`/`6.0`.
- **System-wide window corner radius is a private default, not just a Ghostty/borders concern**: `defaults write -g NSConvolutionOverride1 -float <radius>` (`0` = fully square, `10` = pre-Tahoe/Sequoia, `20` = Golden Gate/macOS 27 default, `26` = Tahoe default) controls corner rounding for Cocoa apps generally, and was used here to make non-Ghostty windows match Ghostty's squared-off look. Undocumented `NSGlobalDomain` key; needs a relaunch or logout/login per-app to take effect, and a handful of apps (dialogs, Weather, Maps, Find My, Books were observed) don't respect it. **As of the macOS 27.0 Golden Gate release this key is ignored** — verified stored correctly (`0`, float) but new windows stayed rounded even after relaunch + `killall cfprefsd`. The Tahoe-era trick is dead on 27; the key has been removed from this system (`defaults delete -g NSConvolutionOverride1`) and all apps use the OS default radius. Don't re-add it without evidence a newer macOS build honors it again.
- **Ghostty doesn't forward modified Option/Alt combos unless explicitly keybound.** By default Ghostty only sends a plain, unmodified key for Option+key combos it hasn't been told to remap, so downstream apps (tmux, pi) can't distinguish e.g. Option+Enter from plain Enter. This repo already worked around it for `alt+left`/`alt+right` (`keybind = alt+left=csi:1;3D`, same for `right`) and now `alt+enter` (`keybind = alt+enter=csi:13;3u`, the CSI-u encoding for Alt+Enter — pi's own `terminal-setup.md` gives the identical `\x1b[13;3u` recipe for WezTerm/Alacritty/Windows Terminal). If another Option-modified chord silently arrives as the unmodified key, add another explicit `keybind = alt+<key>=csi:...` mapping rather than reaching for `macos-option-as-alt` (untested here, and would change Option's behavior globally instead of one key at a time).
- **Ohmyposh foreground tokens.** The git template uses inline `<#hex>…</>` for the icon/quotes while the segment's main `foreground:` covers the branch name. Both surfaces need updates when changing the git segment's palette.
- **zsh Tab completion is threshold-based, not `setopt menu_complete`.** `zshrc` binds `^I` to a custom `zle -C` widget (`tab-complete-threshold`) that calls `_main_complete` (the same function the stock Tab binding uses) and only forces `compstate[insert]=menu` (auto-insert the first match) when `compstate[nmatches]` is under `TAB_MENU_THRESHOLD` (65) — at or above it, oh-my-zsh's default list-first behavior applies instead, since blindly picking "whichever sorts first" isn't useful once the match set is huge. `setopt menu_complete` can't be made conditional on match count, hence the custom widget. Backspace is rebound (`^?`/`^H`) to `_tab_undo_backspace`, which restores the buffer to its pre-Tab snapshot when `$LASTWIDGET` equals whatever is *currently* bound to `^I` — compared dynamically rather than hardcoded, because `eval "$(fzf --zsh)"` (sourced later in the same file) wraps Tab in its own `fzf-completion` widget (falling back to `$fzf_default_completion`, which fzf captures as `tab-complete-threshold` at source time) — so it's `fzf-completion`, not the hardcoded widget name, that ZLE actually dispatches and that `$LASTWIDGET` reports. This makes the undo naturally one-shot (a second consecutive Backspace no longer matches, so it falls through to a normal delete) without needing a separate armed/disarmed flag.
- **tmux requires 3.7+ (for `list-sessions -O`/`switch-client -O`/`display-menu -O` sort-order flags) but avoid `brew install tmux --HEAD`.** `zshrc`'s `t()` bootstrap checks the version and refuses to run below 3.7. Install plain `brew install tmux` (stable, currently `3.7b`), not `--HEAD` — master had, as of July 2026, both a popup-rendering `SIGSEGV` crash (`screen_write_redraw_line`, hit via the `M-g` lazygit popup) and a regression that silently drops `M-Shift` root-table keys (`M-J`/`M-L`/etc. never reach tmux at all; plain `M-`-lowercase keys still worked) introduced somewhere in the active floating-panes/redraw rewrite. Neither was caused by this repo's `extended-keys on` setting — confirmed by toggling it off live with the bug still present. If you ever do need a HEAD build again, verify `M-Shift` binds and a popup running a full-screen TUI (lazygit, nvim) before relying on it. After any tmux binary swap, the **running server** keeps the old binary loaded until `tmux kill-server` + restart — use `tsave <name>` before killing and `tload <name>` after to preserve the session/pane layout.
- **tmux session order is fixed: `float` first, then creation order.** Sessions must be loaded and displayed in one consistent sequence across every surface — the `float` popup session leading, then the rest in the order they were opened. This mirrors the `t` bootstrap in `zshrc` (`tmux new -d -s float` → `tmux new -A -s 'm*'`), so `m*` is normally second. `tsave` records this by capturing each session's `#{session_id}` (a monotonic `$N` creation counter) and `sort_by`-ing groups on it — **not** alphabetically, since jq `group_by` would otherwise sort by name. `tload` loads in that saved order and stable-sorts `float` to the front (a no-op when the snapshot is already creation-ordered) and attaches to the first non-`float` session. The status-right star list (`#{S:…}` in `tmux.conf`) and any other session-listing/switching/rendering must present the same float-first, creation-ordered sequence. Preserve this everywhere when touching session save/restore, listing, switching, or status rendering.

## tmux fzf navigation (`tmux-fzf-nav`)

- **`M-w`/`M-s`/`M-T`** are remade as fzf popup pickers via `tmux_scripts/tmux-fzf-nav`. Wrapper scripts (`tmux-window-ls`, `tmux-session-ls`, `tmux-other-panes-ls`) just `exec` into it — keep them thin so `tmux.conf` bindings stay stable.
- **tmux `\t` in format strings is literal text, not a tab.** Use a shell-level separator (`SEP=$'\x1f'`) or print real tabs from `awk`/`printf`. Parsing tmux `-F '\t…'` output as tabs silently produces one field per row.
- **`display-popup -K` is not supported** by this tmux build (next-3.7) despite local man pages listing it. Using it makes picker launchers return 1 with `unknown flag -K`.
- **Popup/fzf `M-*` keys need two layers**: fzf `--bind alt-*` inside scripts, plus `tmux.conf` conditional pass-through (`if -F '#{||:#{popup_width},#{==:#{pane_current_command},nnn}}'`) so tmux root bindings don't intercept meta keys while a popup or an actual nnn process is focused.
- **`M-j`/`M-k`/`M-q`/`M-o`/`M-K`/`M-g` forward their raw key only inside a real popup or the dedicated `nnn` session** (`#{||:#{popup_width},#{==:#{session_name},nnn}}`) — this is *not* the same condition as M-u/M-n (below). These 6 only ever need forwarding for fzf sub-pickers (fzcd/fzrg's own `M-j`/`M-k`-bound navigation, etc.) reached from inside the `M-d` popup, which is a real tmux popup (`popup_width` alone already covers it) or the `nnn` session by name. A plain `n` alias pane (`alias n="nnn -aH -l 1 -P p"` in `zshrc`) sitting in an ordinary tmux window is neither, so these fall through to their normal tmux action (`select-pane`, `tmux-break-pane`, `fzf-url-open`, extrakto, lazygit-popup) there — which is what you want, since plain nnn itself doesn't bind these keys at all. **Don't broaden this to `pane_current_command==nnn`** — that was tried and reverted: it made these 6 wrongly stop doing their normal thing whenever *any* nnn pane (including a plain `n` alias pane with no fzf sub-picker running) was focused, breaking normal pane-switching (`M-j`/`M-k`) for it.
- **`M-u`/`M-n` root binds are a three-way branch, and *do* use `pane_current_command==nnn`** (unlike the 6 above — this one genuinely needs to fire for a plain `n` alias pane, not just the `M-d` popup). Whenever the focused pane's foreground process is `nnn`, they run `nnn/plugins/.nnn-preview-scroll up|down` to scroll nnn's own preview pane directly — nnn and its pager (moor/less) don't understand M-u/M-n themselves. In other popups (`#{popup_width}`, e.g. fzf pickers), forward the raw key — those bind M-u/M-n themselves via `FZF_DEFAULT_OPTS` for preview scroll. Outside any popup, normal copy-mode scroll. The copy-mode branch must use `run-shell` (not inline `copy-mode -e \;`) because the `if` brace form chokes on the semicolon.
- **`.nnn-preview-scroll` finds the preview pane via a mapping file, not "any other pane in the window."** The naive guess (`list-panes | grep -v self | head -1`) only worked by luck when the tmux window had exactly the 2 panes nnn itself creates (listing + preview, as in the `M-d` popup) — with a 3rd unrelated pane in the window (e.g. a pi/claude pane above a plain `n` alias pane), it could pick the wrong one. `nnn/plugins/preview-tui`'s `start_preview()` (tmux branch) now records `$TMPDIR/nnn-preview-panes/<origin_pane_id>` → `<preview_pane_id>` at split time, using `-P -F '#{pane_id}'` on the `split-window` call to capture the new pane's id; `.nnn-preview-scroll` reads that file first, falling back to the old guess only if no mapping exists or the mapped pane no longer exists. **`origin_pane` must come from `$TMUX_PANE`, not `tmux display-message -p`** — the latter resolves to the window's currently *active* pane (per the attached client), which is not necessarily the pane the script is actually running in; `$TMUX_PANE` is the only unambiguous reference to "this pane" from inside a process running in it.
- **Global fzf meta keys** (`M-q` abort, `M-j`/`M-k` move, `M-u`/`M-n` preview scroll, `M-g` enter/reload rg) are bound in every fzf surface: `tmux-fzf-nav` pickers + rg mode, `tmux-claude-menu`, `nnn/plugins/fzcd`, `nnn/plugins/fzrg`. When adding a new fzf surface, include the same set.
- **Pane-history ripgrep must use per-pane snapshot files, not a TSV.** nvim/opencode panes include ANSI, gutters, soft-wraps, duplicate visible line numbers — flattening into TSV rows breaks parsing and alignment. The rg flow writes `<pane_id>.txt` (plain, for rg) + `<pane_id>.ansi` (ANSI, for preview) + `meta.tsv` (pane→session/window lookup) per search invocation.
- **For pane-history rg, "line" = tmux snapshot row**, not real filesystem/nvim buffer line. True file+line search would need a filesystem-aware mode.
- **rg menu match highlighting**: use `rg --color=always` with `--colors 'path:none' --colors 'line:none'` + explicit `--colors 'match:…'` flags, and `fzf --ansi`. This keeps parsing reliable (path/line are uncolored) while highlighting only the match text.
- **rg preview must not use visible prefixes** (`>>` shifts nvim/opencode rows and breaks background colors). Use zero-width ANSI styling (`\e[4m…\e[24m`) around the matched snapshot row, re-applying after each embedded `\e[0m` reset.
- **`bat --theme=ansi` is the global bat theme** for all tmux/nnn fzf previews (`NNN_BATTHEME=ansi` in `zshrc` + `tmux-nnn-explorer`). Keeps syntax colors aligned with the active terminal palette. The old `vague` TextMate theme is no longer used.

## Claude ↔ tmux session integration (`tmux_scripts/tmux-claude-*`)

A set of scripts gives tmux-native control over the many concurrent Claude Code sessions running across panes. Bound in `.tmux.conf` (lines ~137–145): **`M-b`** = cross-tmux session menu, **`M-G`** = open current session's last response in a split, **`M-P`** = open current session's plan in a split (see the pi-fallback note below), **prefix `.`** = cycle to the next session needing input.

- **Pane↔session join is via the process tree, not cwd.** A `claude` process's **ppid equals its owning pane's `pane_pid`** — this is the only reliable key (many sessions share one cwd, e.g. all the `~/.config` ones). `tmux-claude-ls` is the shared gatherer: it reads `claude/sessions/<pid>.json` (live, accurate: `pid`, `sessionId`, `status`, `name`), resolves each `pid`→`ppid` via `ps`, and matches `ppid` against the `pane_pid` of every live pane. Every other script calls `tmux-claude-ls` and filters its output — don't re-derive the join.
- **`tmux-claude-ls` emits 8 tab-separated fields**: `sessionId pane_id target session_name state name transcript window_name` (the header comment lists 7 — `window_name` was appended later). `state` ∈ `awaiting-permission | waiting | thinking | idle`, mapped from the session JSON's `status` (`busy`→thinking, `waiting`→waiting, `idle`→idle).
- **BSD-awk constraint shapes `tmux-claude-ls`.** It feeds three tagged, tab-delimited streams (`T`=transcript map, `P`=pane map, `S`=session) into a single awk on **stdin** — passing the multi-line pane map via `-v` breaks on BSD awk. Preserve the tagged-record pattern if you extend it.
- **Transcripts are located by `find`, not slug derivation.** `find ~/.config/claude/projects -maxdepth 2 -name '<sessionId>.jsonl'`. The `projects/<slug>` dir name collapses `/`, `.`, **and `_`** to `-`, so substituting the cwd into a slug is unreliable across path types. Transcript JSON keys have **no spaces** (`"type":"assistant"`); extract text with `jq -r '.message.content[] | select(.type=="text") | .text'`.
- **`tmux-claude-menu` is one script with five modes** dispatched on `$1`: outer (no arg → `display-popup` running `--inner`, capturing `ORIGIN_CLIENT` so Enter can `switch-client -c` the *originating* client, since the popup is its own client), `--colorize` (awk-prefixes each row with a 24-bit ANSI color by state — rose/dusty-pink/muted per COLORS.md), `--preview`, `--accept-all` (`k` → sends `Enter` to every `waiting`/`awaiting-permission` pane to approve), `--inner` (the fzf invocation).
- **The `--preview` pane assembles markdown, then pipes through `bat`.** It builds a doc with `## prev claude` / `## you` / `## claude` / `## plan` sections (prev response via `tail -2 | head -1`, guarded against duplicating the latest; plan path grepped from the transcript) and renders it with `bat -l md --style=plain --theme=ansi --terminal-width="${FZF_PREVIEW_COLUMNS:-80}"`. `--theme=ansi` keeps highlight colors on the terminal's vague ANSI palette (same discipline as `nnn/plugins/preview-tui`'s `NNN_BATTHEME=ansi`) — **don't introduce a named bat theme with new hex.** The fzf preview window is responsive: `--preview-window 'right,58%,wrap,<80(down,55%)'` stacks list-on-top/preview-on-bottom under 80 columns; `--preview-wrap-sign=''` suppresses the `↳` wrap glyph.
- **Split placement is centralized in `tmux-claude-open-split`.** `M-G`/`M-P` both call it: 1 pane → split right (`-h`); 2+ panes → split *above the rightmost* pane (`-v -b` targeting the max `pane_left`). Reuse it for any new "open in a split" action rather than re-deriving direction.
- **Plan-path extraction**: `grep -ho 'claude/plans/[a-z0-9-]*\.md' "$transcript" | grep -v -- '-agent-' | tail -1` — subagent plans carry an `-agent-<hash>` suffix and are filtered out; prefix with `~/.config/` for the absolute path.
- **`claude/hooks/session-state.sh` is now wired** into `claude/settings.json`'s `hooks` block — `Notification` (matcher `permission_prompt`) → `awaiting-permission`; `PreToolUse`/`Stop`/`UserPromptSubmit` → `clear`. It writes/clears `/tmp/claude-session-state/<sessionId>`, so `tmux-claude-ls` reports `awaiting-permission` (distinct from question-`waiting`) and the menu tags it PERMISSION + sorts it first. The hook receives the event JSON on stdin (`jq -r '.session_id'`) plus the literal `$1` action from the command string. Changes to the `hooks` block need a Claude restart; edit it as its **own** settings.json change (the auto-mode self-modification classifier can block widening `settings.json`).
- **`M-p` (`tmux_scripts/tmux-pi-prompt`) is a generic scratch-prompt split, not Claude-specific.** Opens an empty buffer in an nvim split directly underneath the triggering pane (horizontal split); `:wq`/`ZZ` pastes the buffer back into the triggering pane as one bracketed paste (`tmux load-buffer` + `paste-buffer -p -d`), populating whatever prompt/input is focused there (pi, Claude Code, opencode, a shell) without submitting. `:q`/`:cq`/an empty buffer sends nothing back. Distinct from pi's own native `ctrl+g`/`externalEditor` (which blocks the same pane and round-trips through `$VISUAL`/`$EDITOR`) — `M-p` is for when you want a separate split instead of taking over the pane.
- **`M-P` is now a dispatcher (`tmux_scripts/tmux-M-P-dispatch`), not a direct bind to `tmux-claude-plan`.** It checks `tmux-claude-ls` for a live Claude session in the current pane first (same join as `M-b`/`M-G`) and only then falls back to `tmux-pi-last-response` for pi panes. **Claude always wins** if both somehow matched (they can't in practice — a pane runs one process) — the check order just means Claude detection is authoritative and pi is the fallback, not the other way around.
- **`tmux-pi-last-response` has no live pid-keyed session-state file to join on** (pi doesn't write anything like Claude's `claude/sessions/<pid>.json`). It instead resolves the pane's direct `pi` child process (`pgrep -P <pane_pid> -x pi`), reads that process's cwd via `lsof -d cwd`, slugs it with the same `/`+`.`→`-` scheme as `pi-config/agent/sessions/<slug>/`, and takes the most recently modified `*.jsonl` in that directory as the active session. This assumes one active pi session per directory — less rigorous than Claude's ppid-based join, but good enough for the common case.
- **ctrl+g uses the default editor (no shim).** An earlier `$EDITOR`-to-tmux-split shim (`tmux-editor-split`) was abandoned — redirecting the editor out of Claude's own pane left that pane blank during the edit. `.zshrc`'s `claude()` is now just `command claude "$@"; printf '\e[4 q'`, so the global `EDITOR=nvim` takes over Claude's pane directly. The shim script is deleted and unreferenced; don't reintroduce it.
- **Window auto-naming detects Claude by its version string.** `.tmux.conf`'s `automatic-rename-format` maps a version-like `pane_current_command` (Claude Code sets its process `comm` to its version, e.g. `2.1.160`) to the label `claude`. If pane names stop showing `claude`, check whether the version-number pattern still matches.

## Claude Code config is itself managed in this repo (skills + smap)

`claude/` is not just cache — it holds hand-authored, user-scope skills (`claude/skills/<name>/SKILL.md`) and `claude/settings.json`. Editing these is real work on this repo, distinct from the session/cache artifacts listed under "Files Claude should not edit".

- **Project-slug scheme (source-of-truth convention).** Several skills derive a per-project slug from the project root by replacing **both `/` and `.`** with `-` (e.g. `/Users/michael.mechenko/.config` → `-Users-michael-mechenko--config`). This must match Claude Code's own `claude/projects/<slug>/` directory naming. Compute it in pure bash (no subprocess, so it never prompts): `tmp="${root//\//-}"; slug="${tmp//./-}"`. Do **not** use `sed 's#[/.]#-#g'` — the substitution form isn't covered by the `Bash(sed -n *)` allow rule and prompts every run.
- **Session map (smap).** Two artifacts track work across sessions:
  - **Durable log** — `~/.config/smap/<slug>.md` (outside the repo, under `~/.config/smap/`, not `claude/`). A pinned `## Findings & Directives` section at the top (durable project notes — one flat list of `- [directive|finding] [id8] <text>`; standing directives flagged `(candidate: CLAUDE.md)` for *manual* promotion), then one markdown block per session, newest first, recording Goal / Done / Open / Files. Session-keyed. Session blocks are detected by the date-prefixed heading `## YYYY-MM-DD — …`, not the first `## ` (which is the pinned section).
  - **In-repo working list** — `SMAP-TODOS.md` at the repo root. Brief open-task list, each task tagged `sessions: <id8>[, ...]`, plus a `## Notes` mirror of the findings/directives. Task-keyed.
  - Skills: `/smap-read` (read-only), `/smap-update` (reads current state first, then overwrites the current session's block by `sessionId` and refreshes `SMAP-TODOS.md`), `/smap-backfill` (recursively reconstructs blocks for *all* past sessions of a project — including git worktrees, which it canonicalizes to the main repo toplevel so they fold into one log — from their transcripts; idempotent, preserve-existing), `/session-review` (propose-only config-improvement review).
  - **`/smap-update` and `/smap-read` canonicalize the repo root to the main checkout** (via `--git-common-dir`, same logic as `/smap-backfill`) — so when run from a git worktree they write/read `SMAP-TODOS.md` and the `<slug>.md` log against the **main** repo, not the worktree. Never write `SMAP-TODOS.md` into a worktree.
  - Each session block carries a one-line `ctx:` under its heading (what/why) for scannability, above `Goal/Done/Open/Files`.
- **`SMAP-TODOS.md` is intentionally gitignored locally** via `.git/info/exclude` (not the tracked `.gitignore`), so it survives branch switches and never shows in `git status`. It exists even though git appears unaware of it — do not recreate or "restore" it on that basis; `/smap-update` owns it.
- **`sessionId` is stable across restarts**, while `claude/sessions/<pid>.json` filenames change per launch. smap keys on `sessionId`, so re-running `/smap-update` after a restart updates the same block rather than duplicating it.
- **Widening `permissions.allow` in `settings.json` can be blocked by the auto-mode self-modification classifier**, even right after a plan was approved. Split narrowing edits (pruning rules) from widening edits (new allows), and keep read-only `Read(...)` additions separate from `Bash(...)` additions.
- **Code-block syntax highlighting is not themeable via the theme JSON.** The custom theme bases on `dark-ansi`, so Claude's syntax colors (and any token not explicitly overridden) inherit the terminal's 16 ANSI colors. To recolor Claude's syntax-highlight blue, override the ANSI slot in `ghostty/config`, **not** the theme — ANSI 12 is currently remapped `#8ba9c1`→`#aeaed1` (accent-secondary lavender) for exactly this. Blast radius: every ANSI-12 consumer (e.g. `bat --theme=ansi`), not Claude alone. See `COLORS.md`.
- **"★ Insight" educational blocks are injected by the `explanatory-output-style` plugin's `SessionStart` hook — not a native output style.** Disable by setting `"explanatory-output-style@claude-plugins-official": false` in `claude/settings.json` `enabledPlugins` (no `outputStyle` key needed; default is already "Default"). Restart Claude to take effect.
- **Commit/PR conventions are centralized in `claude/skills/batch-commit/references/commit-conventions.md`** (Conventional Commits, no emojis, no fluff, imperative, ≤72-char subject; PR body = `## Summary` + `## Test plan`). `/batch-commit`, its `--pr` flag, and `/cx-handoff` all cite it so text is consistent across sessions unless a repo rule overrides. `commit-message-template.md` is now just a pointer to it.
- **`/batch-commit --pr`** assembles a PR title + body and copies a ready `gh pr create …` command to the clipboard (`pbcopy`) — it never pushes and never runs `gh`. User pushes, then pastes.
- **`/tldr`** — read-only session orientation (project, worktrees in play, current goal from smap, open todos, PR state: open / pushed-no-PR / unpushed). **`/cx-handoff`** — builds a paste-ready handoff prompt and copies it (`pbcopy`); modes `--review`/`-r` (context for a review agent verifying a PR) and `--continue`/`-c` (full-context continuation for a compacted session). New-skill trigger entries live in `claude/skills/skill-rules.json`.
- **Statusline is two lines** (`claude/statusline-command.sh`). Line 1: project (`workspace.repo.name`, else dir basename) · `⑂`worktree (`workspace.git_worktree`) · **full** branch (no truncation) · dirty counts · `+N dir` when `workspace.added_dirs` is non-empty. Line 2: model · `[ctx%]` · `PR#<n>` + review-state badge (`pr.number`/`pr.review_state`). Worktree/repo/PR/added-dirs come **natively from the JSON stdin** — no extra `git`/`gh` calls. PR-state colors reuse palette roles (approved→branch lavender, pending→dirty yellow, changes_requested→delete pink, draft→muted).
- **The live MCP-server registry is `claude/.claude.json` (top-level `mcpServers`), NOT `claude/settings.json`.** This build does **not** load `mcpServers` from `settings.json` — servers are registered in `.claude.json` (user scope) via `claude mcp add … -s user`. `.claude.json` is machine state and is **not** tracked in git, so the repo cannot version-control the server list; only the denylist/allowlist keys in `settings.json` are effective. Don't re-add an `mcpServers` block to `settings.json` expecting it to load (it silently won't — that's why a `slack` entry there never appeared in `/mcp`).
- **Firefox is the default browser MCP; Chrome is installed-but-disabled.** `firefox-devtools` (`@mozilla/firefox-devtools-mcp`) and `chrome-devtools` are both registered in `.claude.json`; `settings.json` carries a top-level `deniedMcpServers: [{ "serverName": "chrome-devtools" }]` that durably blocks Chrome while keeping it installed. Denylist entries merge from `settings.json` and nothing overrides them, so Chrome drops from `/mcp` and `claude mcp list` and its tools never load — Claude only ever sees the Firefox tools. To switch back, remove the `deniedMcpServers` entry (and restart).

## pi coding agent config

`pi-config/` is this repo's copy of pi's user config dir, wired up via `PI_CODING_AGENT_DIR` (`zshrc` exports `export PI_CODING_AGENT_DIR=~/.config/pi-config/agent`). Pi normally defaults to `~/.pi`; that path is **not used** here — don't recreate it or write migration steps that assume it. If `~/.pi` reappears (e.g. a shell without the env var sourced), treat it as stale and safe to remove after diffing against `pi-config/agent`.

- **`pi-config/agent/settings.json`** — global pi settings (`theme`, `defaultProvider`, `defaultModel`, permission/trust defaults). Analogous to `claude/settings.json`.
- **`pi-config/agent/themes/vague.json`** — custom pi TUI theme, palette-aligned per `COLORS.md`'s "pi coding agent integration" section. Activated via `"theme": "vague"` in `settings.json`. Unlike the Claude Code theme (11 overrides on a `dark-ansi` base), pi themes are self-contained — all 51 tokens are defined directly, via a `vars` block of palette roles referenced from `colors`. When changing pi's colors, edit this file and update `COLORS.md`'s pi section together, same discipline as every other surface.
- **`pi-config/agent/auth.json`** — provider credentials; treat like `claude/`'s cache dirs — don't inspect/print contents, don't edit unprompted.
- **`pi-config/agent/sessions/`** — per-project transcript logs (dir name is the same `/`+`.`→`-` slug scheme as `claude/projects/<slug>/`). Session/cache artifact — don't edit unprompted, same as `claude/sessions/`.
- **`pi-config/README.md`** — canonical reference for everything under `agent/`: full extension list with provenance and one-line descriptions, the `agent/agents/` + `agent/prompts/` subagent setup, the npm-managed `packages` array, the (not yet installed) web-tooling options comparison, and skills once those land. **Read/update this file, not just this AGENTS.md section, when extensions/agents/prompts/skills change** — this section only covers cross-cutting gotchas.
- **`pi-config/agent/extensions/`** — global extensions, auto-discovered per pi's rules (`extensions/*/index.ts`, one directory per extension). **Naming is uniform: every extension is `<name>/index.ts`, no `pi-` prefix, no `.ts` suffix** — originally-flat example files (`bookmark.ts`, `tools.ts`, etc.) were moved to `<name>/index.ts`, and `pi-goal`/`pi-session-recall`/`pi-skill-toggle` were renamed to `goal`/`session-recall`/`skill-toggle`. `protected-paths/` has a repo-specific tweak: the blocklist is extended with `auth.json`, `.ssh/`, `id_rsa`, `.pem` beyond the upstream defaults (`.env`, `.git/`, `node_modules/`) — preserve that addition if re-vendoring the file. `ask-user/` and any other extension with a real (non-peer) npm dependency needs its own `npm install --ignore-scripts` in that directory — the `ask-user` `prepare` script (`effect-tsgo patch`) fails without dev deps and must be skipped with `--ignore-scripts`. `goal/` and `session-recall/` are forked locally here (not npm-managed) at the user's request — see `pi-config/README.md` for why and how to pick up upstream changes by hand. `skill-toggle/`'s upstream entry point is `src/index.ts`; a top-level `index.ts` re-export exists for auto-discovery, but its `package.json` also carried a `"pi": { "extensions": ["./src/index.ts"] }` manifest field, which pi's `resolveExtensionEntries()` checks *before* falling back to a bare `index.ts` — so the manifest silently won every time and the shim never actually took effect. This made pi resolve (and label, in the startup `[Extensions]` panel) the extension via `src/index.ts` directly, showing up as a bare `src` entry. Fixed by deleting the manifest field from `package.json` so discovery falls through to the shim and labels correctly as `skill-toggle`. See `pi-config/README.md`'s `skill-toggle/` bullet for the full mechanism. npm-managed packages (`@dreki-gg/pi-lsp`, `pi-ast-grep`) keep their real upstream names; the uniform-naming rule applies only to locally vendored/forked extensions, not pi-tracked npm packages. `pretty/` and `diff/` are forked locally (not npm-managed) from `heyhuynhgiabuu/pi-pretty` and `heyhuynhgiabuu/pi-diff` — same `package.json`-manifest-omission trick as `skill-toggle/` (top-level `index.ts` shim re-exporting `src/index.ts`, no `pi.extensions` field in `package.json`), plus their own `npm install`-ed `node_modules/` since both have real runtime deps (Shiki, `@ff-labs/fff-node`, `diff`, `xxhash-wasm`). `pretty/` bundles its own FFF and replaces built-in `find`/`grep`/`read`/`bash`/`ls` rendering; `diff/` replaces built-in `write`/`edit` output with syntax-highlighted diffs and adds a stale-`oldText` edit guard. `prompt-stash/` reimplements Claude Code's Ctrl+S "stash or restore prompt" (`registerShortcut("ctrl+s")` + `ctx.ui.getEditorText`/`setEditorText`): non-empty editor → stash text + clear; empty editor with a live stash → restore. In-memory per-process only, no cursor-position/pasted-image restore (not exposed by pi's extension API) — written from scratch, not vendored.
- **`pi-config/agent/extensions/web-tools/`** is a fork, not a straight vendor copy: upstream (`dmmulroy-config`) called dmmulroy's personal Exa proxy with no caller-side API key; this fork calls Exa's official `https://mcp.exa.ai/mcp` endpoint directly with `$EXA_API_KEY` (sent as the `x-api-key` header). See `pi-config/README.md`'s web-tools section for the exact diff (`settings.ts`, `types.ts`, `providers/exa.ts`, `websearch.ts`) before re-syncing from upstream.
- **`pi-config/agent/settings.json` `packages` array** — npm-installed pi packages managed via `pi install npm:...` / `pi remove` (writes here automatically): `@dreki-gg/pi-lsp` (LSP tools, all servers disabled by default), `pi-ast-grep` (read-only structural search, no rewrite in v0). `@ff-labs/pi-fff` was removed — its `find`/`grep` replacement is now covered by the bundled FFF inside the forked-local `pretty/` extension (see above); running both would double-register `find`/`grep`. Installed packages live under `pi-config/agent/npm/node_modules/` (gitignored, same as `pi-config/agent/extensions/*/node_modules`).
- **`pi-config/agent/extensions/extension-toggle/`** is forked locally (not npm-managed) from `@petechu/pi-extension-toggle`, same treatment as `goal/`/`session-recall/` — `/extension-toggle` (or Ctrl+Shift+E) enables/disables extensions, skills, prompts, and themes, including bare auto-discovered resources like everything else in `pi-config/agent/extensions/`, via native `-path`/`+path` settings filters (no file renaming). `header/`'s enabled/disabled extension-count summary line reuses the same `DefaultPackageManager`/`SettingsManager` resolution internally.
- **`pi-config/agent/extensions/footer/` and `header/`** duplicate the dashboard footer/header from `davis7dotsh/my-pi-setup`'s `ui-customization/index.ts`, split into two extensions and rewired to pi's own built-in data sources instead of that repo's companion `git-info`/`model-info` pub-sub extensions (not vendored, out of scope). `header/`'s logo spells lowercase "pi" out of repeated `p`/`i` characters (not upstream's block-drawing art) — see `pi-config/README.md` for the pixel grid. Both use theme roles (`accent`/`muted`/etc.), never hardcoded hex.
- **No emoji/pictograph symbols in pi output** unless explicitly requested — stated in `pi-config/agent/AGENTS.md`'s Communication section. `permission-gate/` and `plan-mode/` had hardcoded pictograph glyphs removed (⚠, 📋, ⏸, ☑, ☐ → plain text / `[x]`/`[ ]`); plain typographic symbols already idiomatic in vendored TUI extensions (✓/✗, →/↑/↓, ❯) are not emoji and were left alone.
- **`permission-gate/`** auto-allows `rm`/`chmod`/`chown` bash commands without a confirmation prompt when every path argument resolves inside `/tmp`, `/private/tmp`, or `$TMPDIR` (scratch/test dirs), with `..`-traversal guarded against escaping that confinement. `sudo` never auto-allows regardless of path (privilege escalation, not a path-scoped action).
- Web search/browse tooling: `web-tools/` (forked, Exa-backed `webfetch`+`websearch`) is installed and uses `$EXA_API_KEY`. `pi-web-browse` (headless-CDP) and Exa MCP + `pi-mcp-bridge` were evaluated and not chosen — see `pi-config/README.md` for the comparison if revisiting.

- **`pi-config/agent/AGENTS.md` has a `## Response Shaping` section** distilled from the `i-have-adhd` skill (github.com/ayghri/i-have-adhd), with the ADHD framing dropped and only the concrete guidance kept (answer/next-action first, number multi-step work, one concrete next action when work is left open, don't fold in unrelated issues, concrete time/effort estimates, plain cause+fix for errors, cap lists at 5, no recap/closer fluff). Appended to `AGENTS.md` rather than added as a skill — the source skill's own trigger is "every message," which is what a global instructions file does, not what a skill (which needs to be noticed as relevant) does.
- **`tmux.conf` sets `extended-keys on` + `extended-keys-format csi-u`** (near the top, alongside the M-Shift-binding NOTE) so pi's Shift+Enter/Ctrl+Enter are distinguishable from plain Enter. This is safe with the `M-Shift` root-table binds (`M-J`/`M-L`/`M-W`/...) despite the NOTE's earlier caution against `extended-keys 'always'` — `on` only forwards extended sequences to panes whose child process explicitly requests them (pi does; plain shells/nnn/etc. don't), and doesn't touch tmux's own root-table key recognition (that comes from the terminal's `extkeys` feature, already on for `xterm-ghostty`, independent of this option). `always` forces forwarding even to apps that never asked, which is what broke things previously — don't switch back to it.

## "Building" / reloading

- **tmux**: `prefix r` (= `C-Space r`) — reloads `~/.config/tmux.conf` (loaded at server start via the `~/.tmux.conf` shim which `source-file`s it).
- **Ghostty**: `cmd+shift+r` — reloads `~/.config/ghostty/config`.
- **zsh**: `source ~/.zshrc` (or open a new shell). The real config is `~/.config/zshrc`; `~/.zshrc` is a one-line shim that sources it (`$ZDOTDIR` is unset).
- **nvim**: restart, or `:Lazy reload <plugin>` for hot-swappable changes.
- **ohmyposh**: re-render the prompt by pressing enter; no config-reload command needed.
- **AeroSpace**: `prefix r` (= `C-Space r`) — reloads `~/.config/aerospace/aerospace.toml`. (Service mode `r` also reloads; bind is `cmd-shift-enter` → `mode service` → `r`.)
- **SketchyBar**: `cmd-ctrl-alt-o` (Hammerspoon keybind — kills and relaunches with the config; the sole reload path), or from a shell `pkill -x sketchybar && sketchybar -c ~/.config/sketchybar/sketchybarrc`. Avoid `sketchybar --reload` — it can't recover a wedged daemon, and re-adding the right-block items stacks them overlapping (see the bar bullets above). On monitor attach/detach SketchyBar destroys and recreates all bars and re-runs `sketchybarrc` — that's why startup cost matters there.
- **Hammerspoon**: reload its config (Hammerspoon menu → Reload Config, or `hs.reload()` via CLI). `hs -c "..."` invocations from AeroSpace use the live globals; a config reload picks up new `_G` exports.
- **Claude Code**: changes to `settings.json`, `themes/`, `statusline-command.sh`, or skills (`claude/skills/`) require a Claude restart to take effect (renamed skills, new permission rules, etc.).
- **pi**: theme files hot-reload if the active custom theme is currently selected (`pi-config/agent/themes/vague.json`) — no restart needed for color tweaks. `settings.json` changes (provider/model/trust defaults) need a pi restart.
